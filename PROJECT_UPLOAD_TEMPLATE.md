# 📋 Project Upload Template for Admin Panel

This document provides a template and guidelines for uploading projects to your portfolio via the admin panel at `https://admin.aadilkhan.site`.

---

## 📁 REQUIRED Fields

### 1. **Project Title** *(Required)*
- Keep it concise and professional
- Examples: "Portfolio Website", "E-commerce Platform", "Task Management App"

### 2. **Short Description** *(Required)*
- 1-2 sentences for project cards
- Highlight the main purpose
- Max ~100 characters for best display
- Example: "Personal portfolio website with cyber theme, animations, and contact form integration."

### 3. **GitHub URL** *(Required)*
- Full GitHub repository URL
- Example: `https://github.com/hijack-00/portfolio-website`

---

## 📁 OPTIONAL But Recommended Fields

### 4. **Detailed Description** *(Recommended)*
- Full project overview for the details page
- Include:
  - What problem it solves
  - Target audience
  - Key objectives
  - Project scope

### 5. **Technologies Used** *(Recommended)*
- Add each technology separately using the + button
- Examples: Next.js, React, Node.js, MongoDB, TypeScript, Tailwind CSS, Firebase, Flutter, etc.
- Limit to 4-6 main technologies for best display

### 6. **Project Link**
- Live website URL or APK download path
- For websites: `https://aadilkhan.site` 
- For APKs: `/apk/app-name.apk` (relative path)

### 7. **Link Type** *(Required)*
Options:
- `website` - For live web apps
- `apk` - For Android apps (shows download button)

### 8. **Status** *(Required)*
Options:
- `Active` - Currently being developed/maintained
- `Deployed` - Live and in production
- `Development` - Under active development
- `Beta` - Testing phase
- `Completed` - Finished project
- `Maintained` - Stable, receiving updates

### 9. **Order**
- Number for display order (lower = appears first)
- Default: 0

---

## 📁 DETAILED INFORMATION Fields

### 10. **Role/Position**
- Your role in the project
- Examples: 
  - "Full Stack Developer"
  - "Lead Developer"
  - "Solo Developer"
  - "Backend Developer & Project Lead"

### 11. **Client/Company**
- Who the project was for
- Examples:
  - "Personal Project"
  - "Freelance Client - John Doe"
  - "Company Name"
  - "Open Source Community"

### 12. **Team Size**
- How many people worked on it
- Examples: "Solo", "1", "3", "5-10"

### 13. **Duration**
- How long the project took
- Examples: "2 weeks", "3 months", "Ongoing", "6 months"

### 14. **Completion Time**
- Total development hours or timeline
- Examples: "80 hours", "120 hours", "Ongoing", "Continuous"

### 15. **Work Done**
- Describe what YOU specifically built
- List your responsibilities
- Include technical implementations

### 16. **Key Features**
- Add each feature separately using the + button
- Keep each feature to 1 short sentence
- Examples:
  - "Real-time data synchronization"
  - "Admin panel with CRUD operations"
  - "Responsive design for all devices"
  - "Dark mode with smooth transitions"

### 17. **Challenges Faced**
- Technical problems you encountered
- How you solved them
- Shows problem-solving skills

### 18. **Learnings & Takeaways**
- What you learned from the project
- Skills improved
- Technologies mastered

---

## 📸 MEDIA Fields

### 19. **Main Screenshot** *(Recommended)*
- Featured image for project cards
- Recommended: 1200x800 pixels or 16:9 ratio
- Formats: PNG, JPG, WebP
- File size: Under 2MB

### 20. **Additional Screenshots**
- Gallery images for project details page
- Can upload multiple
- Show different features/pages

## 💡 Tips for Best Results

1. **Screenshots**: Take clean, high-quality screenshots showing key features
2. **Technologies**: Only list technologies you actually used significantly  
3. **Description**: Write for potential clients/employers - be professional
4. **Features**: Be specific about what makes your project unique
5. **Challenges**: This shows your problem-solving abilities - be honest
6. **Order**: Use lower numbers (1, 2, 3) for projects you want to showcase first

---

## ⚠️ Common Mistakes to Avoid

- ❌ Leaving short description empty (required!)
- ❌ Using vague descriptions like "A cool app"
- ❌ Adding 20+ technologies (stick to main ones)
- ❌ Low quality or tiny screenshots
- ❌ Missing GitHub links
- ❌ Not setting the correct status
